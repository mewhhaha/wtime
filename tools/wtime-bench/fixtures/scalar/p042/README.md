# P042 supplemental dispatch-pattern proposal

This staged packet addresses the P042 task's requirement to measure monomorphic, polymorphic, churn, and mutation-between-batches behavior while leaving the default 85-row `scalar` selection unchanged.

It contains five original WAT drafts, an independent source-derived typed-i32 oracle model, a manual-oracle record, dual MIT/Apache license texts, proposed workload rows, and a proposed task-local timing contract. The added named selection would contain the existing 85 scalar IDs plus 25 rows: 20 supplemental primary rows across n=17,32,1024,10000 and five n=0 controls. The resulting single compare report has 110 rows, 30 primary, and 80 protected. The main P042 gate must consume this combined report so missing or inconclusive supplemental results prevent adoption.

The current compare.py imports scalar_workloads.py for scalar rows, so installation must merge the source-derived P042 oracle families into that existing model (the packet sidecar is review material, not a drop-in registry module). The same-result target functions intentionally compute x+1 with different expressions. That makes every timing row compatible with the fixed `result=n` oracle, but it cannot prove that replacement or cache invalidation selected the right function. Separate P042 correctness tests must use distinguishable target results and prove two-entry hits, third-target eviction, target replacement, null/OOB/type mismatch, Store identity, and generation behavior.

The packet is uninstalled and source-only. WAT bytes are not encoded or validated; no benchmark binary, timing, or runtime result is included. The `registry-rows-proposal.json` has explicit pending hash placeholders and is not valid for installation until fixture encoding/validation and immutable source hashes are recorded. The timing contract and selection proposal are plans, not executed evidence.


P042 staged scope integration: the installed workload registry keeps the original `scalar` selection unchanged at 85 IDs and adds `scalar-p042-cache` as one combined 110-row timing selection. Its single gate contract uses 30 primary and 80 protected rows. The separate diagnostic contract stays on the original 85-row scalar selection with 10 primary and 75 protected rows. The completed `p042-fixture-validation-v1` receipt must be validated and hash-bound before the combined registry is installed and before the fresh P042-before archive is created.
