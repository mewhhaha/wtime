## Input/output contract

An optional AArch64 Linux backend implements the same small numeric contract with correct ABI/cache maintenance; native execution evidence is mandatory for a support claim, cross-compilation alone is insufficient.

## Implementation recipe

1. Implement only fixed numeric load/store-slot/add/xor/compare/branch forms and the existing helper-exit ABI, declining the rest.
2. Audit instruction encodings, branch ranges, callee saves/stack alignment and required instruction-cache synchronization at RX publication.
3. Cross-check generated bytes and cross-compile where available, then run native differential/accounting/W^X tests on an actual AArch64 target.
4. Collect target/toolchain/source-bound measurements and report missing native infrastructure as blocked; preserve the original T166/T169 native-verification status separately.
5. Forward the explicit `native-aarch64` setting through the harness/policy integrator and record actual optimized/fallback counts. Persistent research selectors are nondefault; reversible changes to an existing tier use before/after artifacts and are selected only by their gate.
6. Guard AArch64-specific tests by target and require at least three actually executed native cases on AArch64. An x86 run with zero matching cases is unrun, not a passing native gate.
7. Attach the separately labeled optional-build report to the performance decision, alongside the default build report; a default-only build cannot establish native/experimental build cost.

## Meaningful cases

- Out-of-range branch/slot forms decline before mapping publication.
- Actual native numeric/fuel/cancel/ABI tests pass with nonzero counts.
- Cross-only evidence cannot mark AArch64 supported or the original native gate complete.
