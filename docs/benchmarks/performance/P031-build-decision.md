# P031 predeclared promotion and build rules

This is a proposal, not executed evidence. Preserve the unchanged 85-workload scalar portfolio. The primary five rows are call_overhead and dynamic API calls at n=1,32,1024,10000. The remaining80 rows are protected, including dynamic API n=0/17, guest direct/indirect/tail calls, ordinary recursion, changing tables, call_ref, host controls, arithmetic and structured control. The targeted cost is outer activation-vector allocation across repeated public guest invocations. Nested host reentry, cleanup and detached-continuation ownership are correctness/path coverage; the current scalar portfolio has no timed reentrant-callback family, so do not infer its speed from ordinary host calls.

Require supported warm primary gains in both independent runs and every existing protected/cold threshold and confidence rule. Do not change targets/thresholds after measurements. The exact shared-batch tooling must confirm both sides at >=20ms across all85 scalar rows using the existing CLI, retain170 calibration records and every bounded attempt, and keep all later timed pairs unfiltered. Calibration does not guarantee every later noisy pair meets20ms; report observed short intervals separately.

Before any production edits, collect one quiet predecessor build and archive the immediate predecessor as P031-before, preserving P001. Collect exactly one quiet candidate build with matching toolchain/settings. Require every gates.RELATIVE_LIMITS ratio <=1.25, all hard budgets, stable sources and zero default external dependencies. Runtime-leaf rebuild is separately reported, not substituted into those six fields. No retry of failed candidate build samples.

The pool is lazy, retains at most two idle activations and at most256KiB including actual outer-vector capacities, idle storage and pool header. Idle entries contain zero logical frames, Values and prompts; nested vectors and metadata owners are dropped. Move active ownership out before guest execution/host callbacks, never hold a pool loan across reentry, and return cleared buffers after every Result. Published values and detached continuations own their separate lifetimes. Oversized/failed retention allocation declines the cache without changing an already completed guest outcome. Returned Values must have independent owned storage; failure to reserve result copy falls back to transferring the old stack, without a new guest error.

Private tests must prove actual pointer/capacity reuse through decoded dispatch, distinct simultaneous outer/reentrant ownership, empty bounded idle storage on success/trap/depth/host error, exact returned float bits, exception-root publication/reclamation and detached continuation survival after an unrelated invocation. Reference agreement is semantic compatibility only. All allocation/path diagnostics are cfg(test) and absent from production timings. Preserve source fuel, cancellation, depth/operand limits and existing cleanup semantics. Retain failed drafts/actual failures, hashes and all raw reports. Revert a rejected default candidate with fresh source mtimes and execute restored tests/build checks. No optimization or speed claim follows merely from this policy file.
